Spec: YouTube-Steuerung via postMessage (generisch, ohne window.YT)

Datum: 2026-07-21 · Betrifft: Functions/PlayerGlobalControl-ActionGenericVideo.js (aufgerufen von PlayerGlobalControl.lua)

Ziel

Eingebettete YouTube-Player (<iframe src=".../embed/...">) auf beliebigen Seiten fernsteuern — wie native <video>/<audio>-Tags. Testfall: http://cc.pixil.de/yt-mini.html?v=Ti3Kt1WlZUM&t=71. Generisch, nicht an eine bearbeitbare Testseite gebunden.

Root Cause — warum der bisherige Ansatz nicht funktionieren kann

Der alte YouTubeIframeAdapter lädt die YouTube-IFrame-API und erzeugt einen YT.Player. Das ist hier prinzipbedingt unmöglich:

  1. Isolated World. JS läuft via activeTab.execute() (JXA) in einer isolated world. DOM geteilt, Globals nicht → window.YT bleibt undefined.
  2. Globals persistieren nicht. Jeder execute startet eine frische world → die ganze globalThis-Zustandsmaschinerie ist wirkungslos.
  3. CSP blockiert die Brücke. Ein injiziertes <script> (main world) wird durch script-src 'self' https://www.youtube.com verhindert.

Nachgewiesener Ansatz: direktes postMessage

Ein Embed mit enablejsapi=1 ist nur ein postMessage-Protokoll. Aus der isolated world erreichbar: das <iframe> aus dem DOM holen und iframe.contentWindow.postMessage(...) senden. Kein window.YT, keine Injection, kein CSP-Problem.

Architektur

Grundgerüst bleibt: MediaController + Adapterliste mit detect(). Interface pro Adapter unverändert.

  • NativeMediaAdapter (echte <video>/<audio>): unverändert.
  • YouTubePostMessageAdapter (neu): ersetzt YouTubeIframeAdapter vollständig.

Entfällt ersatzlos (war nur Diagnose-Infrastruktur): YT.Player-Erzeugung, IFrame-API-Loading/Polling/Timeout, globalThis-State, Context-Probes, normalizeDebugValue, runInPageContext.

static detect() — idempotent, Contract { mediaAdapter, status }

  1. iframe suchen (youtube.com/embed/ + youtube-nocookie.com/embed/). Keins → null.
  2. Listener installieren, falls nicht (Guard: dataset.pgcYt === "1", kein globalThis). Er filtert infoDelivery und schreibt nach dataset.pgcYtState (JSON).
  3. Fehlt enablejsapi=1 → auf load Handshake registrieren, iframe.src neu setzen, Overlay „verbinde…" → { mediaAdapter:null, status:"YouTube verbindet…" }.
  4. Sonst Handshake senden. Cache gefüllt → { mediaAdapter:new …, status:"ready" } + Overlay entfernen. Cache leer → { mediaAdapter:null, status:"YouTube verbindet…" }.

State-Cache

dataset.pgcYtState = JSON { currentTime, playbackRate, playerState, duration, rates, at }. Listener merged jede infoDelivery (nur vorhandene Felder).

postMessage-Protokoll (Referenz)

// Command
iframe.contentWindow.postMessage(
  JSON.stringify({event:"command", func:"seekTo", args:[200, true]}), "*");

// Handshake (startet infoDelivery)
iframe.contentWindow.postMessage(
  JSON.stringify({event:"listening", id:1, channel:"widget"}), "*");

// Antwort: message-Event, JSON.parse(e.data).event === "infoDelivery", Daten in .info

playerState: -1 unstarted · 0 ended · 1 playing · 2 paused · 3 buffering · 5 cued. Voraussetzung: enablejsapi=1 + passender origin (setzt yt-mini.js bereits).

Warmup-Verhalten (Kaltstart)

  1. detect() installiert Listener, rüstet ggf. enablejsapi nach, sendet Handshake, zeigt Overlay „YouTube verbindet…" (Div der Parent-Seite über dem iframe).
  2. Erste infoDelivery → Adapter ready, Overlay weg, Steuerung normal.
hyper+O (setSavedWindow) löst bei unbekannter Domain ohnehin isGeneric → detect() aus und stößt so Setup + Warmup an, bevor die erste Steuer-Taste kommt. Ein evtl. nötiger enablejsapi-Reload kostet einmalig einen „Warmup-Druck".

Lua-Seite

PlayerGlobalControl.lua bleibt unverändert. Für cc.pixil.de läuft der bestehende Pfad: getAppActions → isGeneric → Adapter erkennt iframe → getMediaType() wahr → Domain als generic.video → ActionGenericVideo(...).

YAGNI / später

  • Weitere Provider (Vimeo …) über zusätzliche Adapter — nicht Teil dieser Spec.
  • Mehrere gleichzeitige iframes — vorerst querySelector (erstes Match).

Teststrategie

Verifikation über den echten JXA-Pfad (nicht chrome-devtools — andere World/Instanz): ein Runner findet den yt-mini.html-Tab per URL und ruft tab.execute({javascript}). Prüfpunkte: iframe erkannt · enablejsapi nachgerüstet · Cache füllt sich · Commands verändern den Cache erwartungsgemäß.
