Spec: YouTube control via postMessage (generic, without window.YT)

Date: 2026-07-21 · Affects: Functions/PlayerGlobalControl-ActionGenericVideo.js (called from PlayerGlobalControl.lua)

Goal

Remote-control embedded YouTube players (<iframe src=".../embed/...">) on any website — like native <video>/<audio> tags. Test case: http://cc.pixil.de/yt-mini.html?v=Ti3Kt1WlZUM&t=71. Generic, not tied to an editable test page.

Root cause — why the previous approach cannot work

The old YouTubeIframeAdapter loads the YouTube IFrame API and creates a YT.Player. That is fundamentally impossible here:

  1. Isolated world. JS runs via activeTab.execute() (JXA) in an isolated world. DOM shared, globals not → window.YT stays undefined.
  2. Globals don't persist. Each execute starts a fresh world → the whole globalThis state machinery is ineffective.
  3. CSP blocks the bridge. An injected <script> (main world) is blocked by script-src 'self' https://www.youtube.com.

Proven approach: direct postMessage

An embed with enablejsapi=1 is just a postMessage protocol. Reachable from the isolated world: get the <iframe> from the DOM and call iframe.contentWindow.postMessage(...). No window.YT, no injection, no CSP problem.

Architecture

Skeleton stays: MediaController + adapter list with detect(). Per-adapter interface unchanged.

  • NativeMediaAdapter (real <video>/<audio>): unchanged.
  • YouTubePostMessageAdapter (new): fully replaces YouTubeIframeAdapter.

Removed entirely (only diagnostic infrastructure): YT.Player creation, IFrame API loading/polling/timeout, globalThis state, context probes, normalizeDebugValue, runInPageContext.

static detect() — idempotent, contract { mediaAdapter, status }

  1. Find iframe (youtube.com/embed/ + youtube-nocookie.com/embed/). None → null.
  2. Install listener if absent (guard: dataset.pgcYt === "1", not globalThis). It filters infoDelivery and writes to dataset.pgcYtState (JSON).
  3. Missing enablejsapi=1 → register handshake on load, set iframe.src (reload), overlay "connecting…" → { mediaAdapter:null, status:"YouTube connecting…" }.
  4. Else send handshake. Cache populated → { mediaAdapter:new …, status:"ready" } + remove overlay. Cache empty → { mediaAdapter:null, status:"YouTube connecting…" }.

State cache

dataset.pgcYtState = JSON { currentTime, playbackRate, playerState, duration, rates, at }. Listener merges each infoDelivery (present fields only).

postMessage protocol (reference)

// Command
iframe.contentWindow.postMessage(
  JSON.stringify({event:"command", func:"seekTo", args:[200, true]}), "*");

// Handshake (starts infoDelivery)
iframe.contentWindow.postMessage(
  JSON.stringify({event:"listening", id:1, channel:"widget"}), "*");

// Reply: message event, JSON.parse(e.data).event === "infoDelivery", data in .info

playerState: -1 unstarted · 0 ended · 1 playing · 2 paused · 3 buffering · 5 cued. Preconditions: enablejsapi=1 + matching origin (already set by yt-mini.js).

Warmup behavior (cold start)

  1. detect() installs the listener, adds enablejsapi if needed, sends the handshake, shows overlay "YouTube connecting…" (a div on the parent page over the iframe).
  2. First infoDelivery → adapter ready, overlay removed, controls normal.
hyper+O (setSavedWindow) already triggers isGeneric → detect() for an unknown domain, kicking off setup + warmup before the first control key. A possibly needed enablejsapi reload costs a one-time "warmup press".

Lua side

PlayerGlobalControl.lua stays unchanged. For cc.pixil.de the existing path runs: getAppActions → isGeneric → adapter detects iframe → getMediaType() truthy → domain as generic.video → ActionGenericVideo(...).

YAGNI / later

  • Additional providers (Vimeo …) via extra adapters — not part of this spec.
  • Multiple simultaneous iframes — for now querySelector (first match).

Test strategy

Verify via the real JXA path (not chrome-devtools — different world/instance): a runner finds the yt-mini.html tab by URL and calls tab.execute({javascript}). Checks: iframe detected · enablejsapi added · cache fills · commands change the cache as expected.
